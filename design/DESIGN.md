# RelayPilot — 桌面交互原型设计契约

更新日期：2026-11-26。版本：原型 v0.3，追加 iPhone 伴随端契约；桌面既有行为保持。

本文件描述当前可编辑 HTML 原型的设计与交互边界，只记语义、决策与边界，不记数值；原型模拟不是实际宿主运行证据。

**真源分工**：颜色、字体栈、字号、圆角、间距与动效时长的具体值以 `design/prototype/shared.css` 为唯一真源（亮暗成对）；本文件只记语义名、用途与决策（2026-11-23 按家族最小文档标准瘦身）。改值改 CSS，改语义改本文件。桌面实现状态以本文件平台差异节的 owner 声明为准。当前产品仍按架构实验定位，暂不销售；无 VPN、节点、流量售卖、账户或商业激活界面。

## 目标与受众

面向需要管理本地路由配置、定位规则问题的桌面用户。围绕三个问题组织体验：现在有什么需要处理、路由结果是否符合预期、怎样安全修正。

原型是 macOS、Windows、Linux 桌面实现及 iPhone 伴随端遵循的信息架构与交互规格；技术线与当前落地状态以平台差异节的 owner 声明为准。HTML 中的浏览器机制不等同于原生实现方式。

## 当前交付与入口

- `index.html`：桌面／移动端分组导航与移动状态评审入口。
- `prototype/connect.html`：运行概览入口。
- `prototype/trace.html`：路由检查入口。
- `prototype/profiles.html`：配置库入口。
- `prototype/settings.html`：设置入口。
- `prototype/shared.css`：亮暗主题、布局和组件样式。
- `prototype/app.js`：共享界面、主题、图标、规则模拟与桌面／移动呈现分支。
- `prototype/mobile-overview.html`：iPhone 伴随端运行概览。
- `prototype/mobile-trace.html`：iPhone 伴随端路由检查简版。
- `prototype/mobile-profiles.html`：iPhone 只读配置库。
- `prototype/mobile-settings.html`：iPhone 精简设置。

每个入口都使用相同应用外壳，通过本地状态切换页面。页面之间的主要操作不依赖 URL 跳转；独立打开不同 HTML 会创建不同的示例会话。文件无远程字体、脚本或图片依赖。原型只演示交互，不请求真实网络数据。

### glaze 线实现（2026-11-24，#13 S2–S4）

`prototype/` 仍是 UI 基线；产品实现落在 `host/web/`（`index.html` + `app.js`，token 单源 `prototype/shared.css`，文案单源 `shared/i18n`）。S2 落地运行概览与配置库，S3 落地路由检查与诊断导出，S4 落地设置、快速查找与托盘；与原型的差异如下：

- 导航为「运行概览 / 路由检查 / 配置库 / 设置」四项（设置自 S4 起）。
- 配置状态只有「校验通过 / 需要处理」两种（引擎 `library-list` 的 `status`）；原型的「待校验」「legacy 完整配置」是模拟态，不再出现。
- 会话是真实引擎会话：启动先走 `engine-dry-run`，引擎二进制未配置时保持「未运行」并提示；运行中显示回环入站端口，引擎事件进入「操作记录」。切换配置不重启运行中的会话（重启后生效）。
- 已保存目标由概览内联表单添加（仅校验域名格式与重复），结果为 `explain-route` 的 `policy → outbound`；outbound 是引擎出口 id（如 `relaypilot.direct`），不是本地模拟的 `proxy/lab-a`。点击目标进入路由检查。
- 路由检查：「你的预期」只作对照，按目标保存在本机；与计算结果不一致时进入概览「待处理」，并可按预期直接修正（复用单目标路由修改）。「决策过程」直接列出引擎 `explain-route` 返回的步骤文本，不在页面复述规则匹配。
- 诊断导出：`diagnose-route` 生成记录，写入用户在系统保存面板选择的路径（`api/dialog/save` → `api/host/write`，能力授予限定在本机用户）；脱敏开关位于「检查记录与技术详情」内，默认开启（隐藏目标域名与 trace ID），设置页复用同一偏好；设置页的「导出记录」需先在路由检查里检查一个目标，否则按钮禁用并说明原因。
- 设置页按原型落地主题（跟随系统 / 浅色 / 深色，`html[data-theme]`，跟随系统时随 OS 切换）。原型明确不展示语言下拉，实现同样不提供：界面文案跟随系统语言。
- 快速查找：顶栏入口与设置页入口打开同一个对话框（`Ctrl/⌘ K`，非输入状态 `/` 聚焦当前页搜索）；列表为页面、配置与已保存目标，↑ ↓ 在条目间移动、Enter 打开、Esc 关闭。
- 托盘（载体提供）：菜单为「显示窗口 / 各可用配置（当前配置勾选）/ 快速查找… / 前往各页面 / 退出」，文案与勾选状态由页面在每次渲染后提交给载体重建；在托盘里选配置或前往页面，走与页面按钮相同的操作路径（含撤销与提示）。点击托盘图标聚焦窗口；「退出」先经页面停止会话再结束进程，页面无响应时 4 秒后兜底退出。
- 规则编辑器文本为纯规则行（无 `[Rule]` 节头）；校验、预览、保存全部走引擎，页面不自行判定。导入文本接受 Surge 节头，预览逐行说明未导入内容，需勾选确认后才能创建。
- 撤销为单步、基于引擎快照（`library-restore-profile`；切换的撤销是切回上一配置；删除的撤销是恢复快照文件，描述不随快照保留）。已保存目标、路由预期、脱敏与主题偏好保存在 WebView 本地存储。

## 视觉方向

延续现有家族暖灰与陶土色，以专业桌面工具的清晰、克制为方向。品牌颜色来自已有契约，而非重新选择的默认背景风格。页面以文字、留白、分隔线和明确的选中状态形成层级，减少卡片堆叠与胶囊标签。

保留系统字体。正文、操作与次级说明、元数据、章节标题、页面标题、主要会话状态各成字号层级（值见 `shared.css`）。代码、域名、规则与技术标识使用系统等宽字体。没有外部 Web 字体。

| `--surface` | 会话、详情与对话框 |
| `--raised` | 导航、辅助区域 |
| `--line` | 非关键分隔线 |
| `--ink` | 主文字 |
| `--mute` | 辅助文字 |

| `--brand` | 原品牌色保留 |
| `--ok` / `--ok-soft` | 成功文字与标记 / 成功底色 |

原陶土色仍保留为品牌 token；浅色主题操作色加深，深色主题操作色提高明度。浅色主按钮用白字，深色主按钮用深色文字。此次是依据可读性基线采用的设计调整，不表示用户已确认最终色值。

间距节奏、控件/内容/对话框三级圆角均以 `shared.css` 为准。图标为同一套描边 SVG（统一线宽），功能图标通过 `.od-icon` 管理尺寸，不使用 Unicode 字符代替图标。

交互以直接状态反馈为主，进行态具有文字说明；尊重减少动态效果设置。无装饰性动画、背景图片或模拟系统窗口按钮。

## 信息架构

### 运行概览

第一层回答会话状态、当前配置、默认路由与配置校验状态。使用“运行概览”作为任务标题，启动和停止使用简洁操作名称。统一提示栏始终说明所有结果均为本地模拟、不接管真实网络。

待处理数量由当前状态派生：未校验配置、校验错误配置，以及已设预期却不符合的目标。每项都能进入对应详情；没有问题时显示明确的完成状态。默认路由取当前配置中的 FINAL 规则，不硬编码代理出口。目标入口标为“已保存目标”，不冒充实际访问历史。操作记录来自本次交互，不伪装成真实网络日志。

不在首页展示 adapter、digest、编译产物等开发层信息。引擎未调用就不展示虚构的引擎版本、摘要或运行证据。

### 路由检查

输入域名，按当前配置中的示例规则顺序匹配。支持精确域名、域名后缀与 FINAL；输入不包含协议、路径或空格。页面通过统一原型提示明确说明是模拟，不实际连接目标。

展示顺序为目标、预期与计算结果对照、决定结果的规则及修正入口、决策过程、可展开的技术详情。

用户可对当前目标设置“直接连接”“通过策略组”“拒绝连接”或暂不设定。设置预期只改变对照标准，不修改规则。不设预期时不判断符合或异常；预期与当前策略不同时显示原因和“按预期修正”。内置两个目标预置期望供交互演示，新输入的目标不擅自推断预期。预期属于用户意图，撤销规则不会撤销用户设置的预期。

决策过程依次呈现配置载入、规则命中、必要的策略组解析。DIRECT 或 REJECT 命中即终止，不再显示后续代理策略解析。仅策略转发结果展示静态示例出口 `proxy/lab-a`，不声称探测其健康状态。

规则原文与来源可以展开。检查记录的 `trace_id` 使用 `demo-` 前缀，来自目标与当前示例配置版本；不冒充真实引擎 trace。技术详情明确标记无引擎调用、无真实 adapter 版本或 artifact digest，保留可复制记录。

### 配置库

列表与所选详情组成主从结构。区分“当前使用”与“当前查看”，避免点击查看就悄悄切换生效配置。待校验的预置示例需先校验才能使用；完整旧配置显示处理原因与导入入口。

名称与描述搜索采用不区分大小写的包含匹配；可叠加全部、通过、待校验、需要处理四种状态筛选。结果数量来自同一筛选集合。搜索不重建输入框，保持光标位置；详情只显示当前筛选范围内选中的配置，零结果提供清除筛选入口。从首页问题或快速查找打开配置时清除筛选，保证目标可见。校验或保存导致配置离开当前状态筛选时恢复全部状态，让处理结果继续可见。

导入属于独立对话框流程，不常驻占据配置列表。导入成功只创建新配置，不自动激活。切换与删除均需确认；当前使用的配置不提供删除入口。

### 设置

只提供当前实际能演示的设置：跟随系统、浅色、深色主题，导出目标地址脱敏，以及诊断记录导出。增加快速查找入口和键盘操作说明。显示变更保护始终开启；明确 AI 服务未接入。不展示没有行为的语言、目录同步和 AI 数量下拉框。

诊断导出为本地 JSON。开启脱敏时移除目标域名与规则目标，同时不导出目标派生的 trace ID。导出不包含实际网络抓包或系统日志。

## 核心交互契约

### 启动与停止

1. 点击启动，确认当前配置与模拟边界。
2. 展示带说明的校验进行态，期间禁用重复启动。规则校验失败则保持未运行，并将错误列入待处理事项。
3. 校验通过后转为运行中并记录操作事件。运行含义受统一原型提示约束，不代表系统网络已改变。
4. 停止需要确认，返回未运行状态，配置不变，可再次启动。

这些状态不代表引擎健康、系统代理状态或真实联网成功。宿主实现时必须由真实引擎生命周期驱动。

### 路由修改

1. 从路由结果进入“修改路由”。
2. 对当前目标选择 DIRECT、policy-main 或 REJECT。有预期时默认选择用户预期；结果与当前相同则提示无需应用。
3. 预览旧结果、新结果及将新增的 DOMAIN 精确匹配规则。
4. 显式应用到当前示例配置的规则列表顶部。
5. 立即按同一份状态重新计算路由，支持撤销上一项配置变更。

已存在的同目标 DOMAIN 规则由新规则替代，其他规则保留顺序。预览绑定当前配置与版本，配置变化后必须重新预览。修改仅在本次原型会话内有效，不写入真实配置文件。

### 配置导入

1. 粘贴文本或填入内置示例，命名新配置。
2. 解析当前文本，展示可导入规则数量、出口、策略组和逐行排除原因。
3. 有不支持内容时，用户必须勾选明确的排除确认才能继续。
4. 创建独立示例配置，返回配置库查看；使用它需要另行确认。

演示解析范围刻意收窄：仅一个 `127.0.0.1` / `localhost` 的 HTTP 出口、单成员静态 select 组、无附加参数的 DOMAIN / DOMAIN-SUFFIX / FINAL 规则。规则引用必须可解析，必须包含可用 FINAL，FINAL 后的规则列为不可执行内容。其他 section、参数、不可解析出口与策略引用逐行报告，不静默声称兼容。

代理与策略名称在导入后的示例模型中统一映射为 `policy-main` 和 `proxy/lab-a`，预览明示此映射；这不是可导出或可用于生产的 Surge 转换器。


### 校验失败与规则编辑

`office-inline.yaml` 初始只有一条内网规则、缺少 FINAL，状态为待校验。这是明确的本地配置样本，不伪造网络超时或远程服务故障。点击校验后计算实际错误，状态转为需要处理，并说明在末尾添加兜底规则的原因。

规则编辑按每行一条文本处理，支持 DOMAIN、DOMAIN-SUFFIX、FINAL，策略限于 DIRECT、REJECT 与 policy-main。校验检查字段数量、规则类型、域名、策略、FINAL 的存在与位置。错误保留原稿并给出修复说明；可用“添加默认转发规则”补充缺失项，重复或位置错误的 FINAL 仍会被校验拦下。

编辑后必须先校验并预览完整新旧规则，确认保存才更新配置。当前配置的保存立即影响路由计算；其他配置只更新自身，不自动激活。保存绑定配置版本，防止预览后应用到已经改变的配置。失败后返回修改保留草稿，成功后支持单步撤销。

### 快速查找与键盘

顶栏和设置提供同一个快速查找入口。macOS 显示 ⌘ K，其他桌面平台显示 Ctrl K；快捷键触发同一个原生模态对话框。

搜索范围为四个页面、当前配置名称与描述、两个已保存目标。输入建议与选择使用同一集合和匹配规则。↑ ↓ 在实际结果按钮间移动，Enter 打开所选项，搜索框中的 Enter 打开首项，Esc 关闭并恢复焦点。零结果保留输入框与具体提示，不显示旧结果。

非编辑状态按 / 聚焦当前路由输入或配置搜索；不会劫持文本输入中的斜杠。当前已有其他编辑对话框时，快捷查找不会覆盖尚未完成的编辑。

## 状态、持久化与防错

- 配置、活动配置、规则、路由结果与事件由同一会话状态渲染。
- 配置变更提供单步撤销，撤销后生成严格递增的检查记录版本。撤销入口位于通知与顶栏，关闭通知后仍可使用顶栏入口。
- 切换配置、删除配置、启动、停止、应用规则均通过显式确认或影响预览。
- 空输入、非法域名、重复名称、无效名称、无可导入规则、缺少兜底规则、未确认排除内容均有具体反馈。
- 对话框支持取消与 Escape；关闭后焦点返回存活的触发控件或当前导航入口。
- 复制优先使用浏览器剪贴板；不可用时提供可选中文本，不声称复制成功。
- 主题和脱敏偏好在 localStorage 可用时保存；存储不可用时继续使用内存状态。
- 不承诺刷新后保留导入配置或规则修改。
- AI 仅保留“预览 → 显式应用”的产品原则，本轮没有生成式 AI 调用。

## 布局与可访问性

桌面使用侧边导航与正常文档流；主区域不依靠固定高度窗口裁切内容。断点行为：宽屏调整留白 → 中宽收为单列主从布局 → 导航置于顶部 → 最窄单列内容（具体宽度见 CSS 媒体查询）。没有缩放页面来适配小窗口。

按钮和输入使用语义控件；输入有持久标签；错误不在初始状态显示。主操作有可见焦点，状态同时使用文字和图标。路由对照在窄屏转为上下结构，配置搜索和筛选转为单列，问题列表操作不会挤压长文件名。对话框采用原生模态行为与明确关闭路径。内容与辅助文本可以随系统字体放大换行，域名与规则详情允许完整换行。

统一层（三平台必须一致，由本契约与原型锁定）：信息架构（四屏）、会话启动/停止与校验流程、预期对照与「按预期修正」的叙述顺序、导入预览的逐行排除报告、单步撤销、快速查找（⌘ K / Ctrl K）、语义色与层级词汇。因地制宜层（选定宿主后按平台惯例落地，不预画像素）：
